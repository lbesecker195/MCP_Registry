This folder holds `batcher.ex`, the GenServer behind `McpRegistry.Discovery.announce_later/2`. Code on a request path hands it the listings whose pages just went live or changed: an approval, a publish over the API, or a saved article. It holds them for `:batch_window_ms` (one minute in production) and sends them to `Discovery.announce/2` as one request. The official-registry sync skips the batcher and announces its own changes in one call at the end of each run.

Batching matters because IndexNow treats a flood of one-URL requests from one host as spam. A content run that saves a few hundred articles for pages like [the Playwright MCP server](https://ai.mcpharbor.dev/servers/io.github.microsoft/playwright-mcp) would otherwise send a few hundred requests. With the batcher it costs a handful. If the batcher stops, new and updated listings still reach search engines through [the sitemap](https://ai.mcpharbor.dev/sitemap.xml), just more slowly.
